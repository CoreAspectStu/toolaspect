Do Audio Files Have Metadata?

📄 6 min readUpdated November 1, 2026

Yes. Every common audio format carries tags such as title, date, comment and the encoding software, and M4A can hold a GPS location in the same binary atom video files use. We tagged a test recording, converted it six ways and found the location survived every conversion except a deliberate strip. Here's what each format stores and how to check and clean your own files.

Do audio files have metadata?

Yes. Every common audio format has a place for text about the recording: a title, who made it, when, a comment, and the name of the software that encoded it. Music files use these for track names and album art. Voice recordings use the same slots, and that's where the surprises live, because a recorder app can write the date, the device and sometimes the place into a file you then email to someone.

We built a 10-second test tone with ffmpeg, tagged it, saved it in five formats and read the files back with ffprobe and the mutagen library. Here's what each format can hold:

FormatWhere the tags liveTypical fieldsLocation field?
MP3ID3v2 tags (v2.4 by default from ffmpeg)Title, artist, album, date, comment, encoder, cover artNo standard frame; apps use a free-form TXXX field
M4A / AAC (iPhone Voice Memos, iTunes)MP4 "ilst" atomsTitle, artist, date, comment, encoder toolYes, a binary "loci" atom, same as video files
WAVRIFF INFO chunkName, artist, creation date, comment, softwareNo field; often no tags at all
FLACVorbis commentsAny text field you likeYes, as plain text (LOCATION=)
OGG / Opus (WhatsApp voice notes)Vorbis commentsAny text field you likeYes, as plain text

MP3 is the odd one out on location. ID3 has no GPS frame, so apps that want to store one invent a free-form TXXX field, and ours did exactly that. WAV from most recorders has no tags at all, though ffmpeg adds an INFO chunk when you give it tags.

Can a voice recording reveal where it was made?

It can, if the app writes it. Our M4A test file carried a location of 40.7128, -74.0060 in the same "loci" atom that video files use. Two things about that atom matter. It survived an ffmpeg copy untouched. And it's stored as binary, so searching the file for the digits found nothing. A file can carry coordinates that a text search won't show you.

Whether your phone's recorder stores coordinates depends on the app, and we couldn't test every one. Apple's Voice Memos documents a "location-based naming" option that titles recordings after the place you were, so the place name can sit in the title field even when there's no GPS atom. Check with the steps below rather than assuming.

Photos are a different story, and a more common one. If you're worried about pictures, our guide on removing location from photos and the image metadata remover deal with those.

Does converting an audio file remove the metadata?

Mostly no. ffmpeg, and the many apps built on it, copy the global tags from input to output by default, mapping each field to the nearest one in the new format. We converted our tagged files back and forth and checked each result:

ConversionWhat survivedLocation still present?
M4A, copied without re-encoding (-c copy)Everything, including the locationYes
M4A → MP3Everything; the location moved into a text TXXX fieldYes, now searchable as text
MP3 → M4ATitle, artist, album, date, commentNo (nothing to carry)
MP3 → WAVTitle, artist, album, date, comment, as an INFO chunkNo
Any → any with -map_metadata -1Only an "encoder" tag naming ffmpegNo
Same, plus -fflags +bitexactNothingNo

The M4A to MP3 result is the one to remember. The location didn't just survive, it became a plain-text TXXX field, so a conversion meant to "clean up" a file made the coordinates easier to find. Only an explicit instruction to drop metadata removed them.

How do I see what's in an audio file?

  • VLC (Windows, Mac, Linux): open the file, then Tools → Media Information. The Codec tab lists the stream details and the Metadata tab the tags.
  • Windows: right-click → Properties → Details shows title, artists, album and year for MP3 and M4A. It doesn't show custom fields or location.
  • Command line: ffprobe file.m4a prints every tag it understands, location included. mutagen-inspect file.mp3 lists the raw frames, which is how we saw the TXXX fields.

Two gaps we hit. mutagen read nothing from our WAV even though ffprobe listed five INFO fields, so a "no metadata" answer from one tool isn't proof. And neither tool decodes the loci atom into readable coordinates in its default listing; ffprobe showed it, mutagen's default dump didn't.

How do I remove metadata from an audio file?

The reliable way is a copy with the metadata map cleared. The audio isn't re-encoded, so the sound is byte-for-byte the same and the file loses only its tags:

ffmpeg -i memo.m4a -map_metadata -1 -fflags +bitexact -c copy clean.m4a

Without the bitexact flag, ffmpeg writes one tag of its own naming the encoder library, which is harmless but tells a recipient what you used. For MP3 you can also open the file in a tag editor and delete every field, or re-save it with cover art removed. Our browser tools handle images and office documents rather than audio, so the document metadata remover is the right stop for a Word transcript of the recording, not the recording itself.

Which audio format carries the least metadata?

WAV, in practice. Most recorders and editors write a bare RIFF header with no INFO chunk, and there's no room for cover art or a location field. The cost is size: our 10-second mono file was 882,170 bytes as WAV against 83,353 as M4A. If you need a small file with no history, convert to M4A or MP3 with the stripping command above, then check it with ffprobe before you send it. For images, the EXIF viewer does that check in the browser.

Frequently Asked Questions

Do MP3 files have metadata?

Yes. MP3 files carry ID3 tags: title, artist, album, year, comment, encoder and embedded cover art. There's no standard field for GPS location, but apps can store one in a free-form TXXX frame, and a file converted from M4A will have the location moved there as plain text.

Do voice memos have location data?

They can. M4A files have a "loci" atom for coordinates, the same one video files use, and our test file kept it through an ffmpeg copy. Whether your app writes it varies. Apple's Voice Memos can also put the place name in the recording's title when location-based naming is on. Check with ffprobe or VLC.

Does converting audio remove metadata?

Not by default. ffmpeg and apps built on it copy the tags to the new file and translate them to the new format. In our tests M4A to MP3 kept everything including the location. Only an explicit metadata-stripping option (-map_metadata -1 in ffmpeg) removed them.

How do I remove metadata from an audio file?

Run ffmpeg -i in.m4a -map_metadata -1 -fflags +bitexact -c copy out.m4a. The audio is copied unchanged and every tag is dropped. Without the bitexact flag, one encoder tag naming ffmpeg remains. A tag editor that lets you delete all fields works for MP3 too.

Do WAV files have metadata?

Usually very little. WAV can hold a RIFF INFO chunk with a name, artist, date and comment, and ffmpeg writes one if you supply tags, but most recorders don't. There's no standard location field or cover art. Some tag libraries, including mutagen, skip the INFO chunk entirely, so use ffprobe to be sure.
