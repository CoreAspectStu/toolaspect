Do PDF Files Have Metadata?

📄 6 min readUpdated November 2, 2026

Yes. Nearly every PDF carries metadata, and it's stored in two separate places, so a file can look clean in one viewer and still contain your name. Comments and attachments can identify you too. We built a test file, cleaned it six different ways and searched the bytes afterward. Two of those methods were our own tools, and neither got it fully clean.

What metadata can a PDF contain?

More than the Properties box shows. A PDF has two separate metadata stores, and it can also hold things that aren't labeled metadata but work the same way:

Where it livesWhat it holdsWho can see it
Info dictionaryTitle, Author, Subject, Keywords, Creator, Producer, created and modified datesAny PDF reader's Properties box
XMP packetA second copy of much the same, sometimes with edit historyMetadata tools, or a text search of the raw file
CommentsThe author name on every sticky note and highlightAnyone who opens the comments panel
AttachmentsWhole files embedded in the PDFThe attachments panel
Old savesEarlier versions kept when a program appends changes instead of rewritingAnyone who can parse the file

Most PDFs carry something, even if it's only a Producer name and two timestamps. What matters is whether anything in there identifies a person, a client or an internal project.

Where does the metadata come from?

Usually you didn't type it. The program that writes the PDF fills it in from the source document and your account:

Made withTypical fieldsIdentifies you?
Chromium 145, Save as PDF (tested)Title from the page, Creator "Chromium", Producer "Skia/PDF m145", created and modified timesNone
Word, Save as PDFUsually title and author from document properties, Word versionOften your account name
Scanner or copierDevice or firmware name, scan dateSometimes a model or serial detail
Design apps (InDesign, Illustrator)Full XMP, app version, sometimes file historyCan include source file names

We only ran the first row ourselves. The others are typical behavior, and they vary with version and settings. Printing to PDF from a browser leaves out your name, but it does keep the page's title, which on a web app may be the name of a customer or a case. Word is covered in more detail in our guide to removing metadata from Word documents.

How do you check a PDF's metadata?

In Acrobat Reader, press Ctrl+D (Cmd+D on a Mac) and read the Description tab. In Preview, use Tools > Show Inspector. In a browser, our PDF Metadata Editor lists the eight standard fields without uploading anything. On Linux or macOS, pdfinfo file.pdf prints the same fields, plus a "Metadata Stream" line telling you whether XMP is present. That line is the quick way to catch a file whose Info fields are empty but which still has XMP.

What actually removes it? We tested six ways

We built a small test PDF with all eight Info fields filled in, an XMP packet, a sticky note and an attached file. The same fake name went into each. Then we cleaned copies of it and searched the raw bytes for that name. Three things stood out:

  • Blanking Properties isn't enough. With only the Info fields cleared, pdfinfo showed an empty Author while the name still sat in XMP.
  • How you save matters. An incremental save added 436 bytes and left all three plain-text hits in the file, because it appends changes and leaves the old data in place. "Save As" in most apps rewrites the file. Plain "Save" may not.
  • Metadata tools don't touch comments or attachments. Neither of our tools removed them, and neither did blanking fields. Delete those by hand in your PDF app first.

We included our own tools because you should know what they do. Strip All in the editor empties the eight Info fields, but in this test it left the XMP packet readable and kept the creation date, while setting a new modified date. The remover cleared both stores for PDF readers, but the old XMP bytes stayed in the file, unlinked. Both are fine for tidying a title or removing your name from Properties. How do you clean a PDF you really care about?

  1. Delete comments and attachments in your PDF app, and accept or discard any tracked markup.
  2. Clear the metadata, using a tool that handles both Info and XMP.
  3. Rewrite the whole file. In Acrobat Pro, use Sanitize Document. In code, a PyMuPDF save with garbage=4 drops unreferenced data. Our test file reached 0 hits and shrank from 2,647 to 940 bytes this way.
  4. Check the result: run pdfinfo, then search the file for your name with grep -a.

Printing to a new PDF from a browser or the system dialog is the blunt alternative. It usually drops comments, attachments and old saves, but it can change the layout, break links and remove form fields. It won't remove anything visible, so a black box drawn over text needs a real redaction step: see how to redact a PDF.

Frequently Asked Questions

Do PDF files have metadata?

Yes, almost always. Most PDFs have at least a Producer name and created and modified dates, and many also list a title and author. A PDF can hold this in two places, the Info dictionary and an XMP packet, so clearing one may leave the other.

Can a PDF show who created it?

Often, but not reliably. The Author field usually comes from the account or document properties of whoever made the source file, so it may name a colleague or a previous owner. Anyone can edit or delete it, so treat it as a clue and not as proof.

Does saving as PDF remove metadata?

No. Exporting usually copies the title and author from the source document into the PDF. In our test, Chromium's Save as PDF wrote no author but did store the page title, the app name and the time it was created.

Does flattening a PDF remove metadata?

Not by itself. Flattening merges comments and form fields into the page, but the Info fields and XMP packet generally stay. Clear the metadata as its own step and then rewrite the file.

How do I see hidden metadata in a PDF?

Open Properties in your reader for the Info fields. To catch XMP, run pdfinfo and look for "Metadata Stream: yes," or search the raw file for "xmpmeta" with grep -a. Check the comments and attachments panels too, since neither appears in Properties.
