Does WebP Keep Metadata? What Survives Conversion

📄 6 min readUpdated October 25, 2026

Yes, WebP files can keep metadata, including camera details, the date and GPS coordinates. Whether yours does depends on the tool that made it. We built a WebP with location data and ran it through eight common routes: some carried everything through, some dropped it all, and one hid it in a block most readers can't see. Here's what we found, and how to check and clean a WebP.

Can WebP files contain metadata?

Yes. WebP is built on the same RIFF container used by WAV audio, and an "extended" WebP can hold separate chunks for EXIF, XMP and a color profile alongside the image. The format was designed to carry the same metadata as a JPEG, so anything a camera writes, including GPS coordinates, can travel along when a photo is converted.

ChunkWhat it holdsWhere you'll see it
VP8XHeader that says which extras the file hasEvery WebP with metadata or transparency
EXIFCamera, date, author, software, GPSConverted photos, some editors
XMPCreator, copyright, editing history, keywordsAdobe apps, stock and asset tools
ICCPColor profileMost converted photos
VP8 or VP8LThe image itself (lossy or lossless)Every WebP

That said, plenty of WebPs carry nothing. Most come from websites that convert images automatically, and many of those pipelines throw the metadata away. A WebP you made yourself from a phone photo is the case to worry about. Lossless WebP can hold it too; our lossless test file kept the full EXIF block.

Does converting to WebP keep metadata?

It depends entirely on the tool. We built a test WebP with a camera make and model, an author name, the time it was taken, GPS coordinates, XMP and a color profile, then ran it through common routes and checked what came out:

*ImageMagick 6.9.11 complained that our hand-made XMP block was invalid before dropping it, so treat that column as "unclear" rather than proof it always drops XMP.

A few results are worth spelling out. ImageMagick kept the location in WebP and PNG output. Its JPG output was stranger: it wrote the EXIF data without the header readers look for, so Pillow and our viewer's library both reported zero tags, yet the author's name was still sitting in the file's bytes. A "clean" result in one viewer doesn't prove anything is gone. Pillow, the Python imaging library, drops everything on a plain save unless you pass the metadata through on purpose. The browser canvas route, which is how our tools work, kept nothing but a generic sRGB color profile. The test file was one we made, not a real phone photo, so read this as a check on each tool's behavior.

How do I check a WebP for metadata?

Here we need to be straight with you: our EXIF viewer can't read WebP yet. The library it uses rejected every WebP we tried with "unknown file format," even ones with a full EXIF block. It handles JPG, PNG, HEIC and TIFF, so it's still the quick check after you convert. For a WebP itself, use one of these:

  • ExifTool: exiftool photo.webp lists every EXIF and XMP field, GPS included. Our ExifTool alternatives guide has gentler options.
  • webpmux, from Google's WebP tools: webpmux -info photo.webp shows which chunks are present and how big they are. An EXIF chunk of a few hundred bytes or more is worth a closer look.

How do I remove metadata from a WebP?

  • In the browser: run the file through our image compressor with WebP as the output format. It redraws the image on a canvas and saves a fresh file; in our test that removed the EXIF, the GPS and the XMP. Our image metadata remover is built for JPG and PNG, and it always saves a JPG.
  • Command line: exiftool -all= photo.webp, or convert photo.webp -strip clean.webp with ImageMagick. Without -strip, ImageMagick kept the GPS in our test.
  • Check afterwards. Use ExifTool or webpmux on the WebP, or convert a copy to PNG and drop it into the EXIF viewer.

The same pattern runs through every format we've tested: tools that redraw the pixels drop metadata, and tools that convert files often carry it along. If you're working with other formats, see do PNG files have metadata and does converting HEIC to JPG keep metadata.

Frequently Asked Questions

Does WebP support EXIF data?

Yes. The extended WebP format has dedicated chunks for EXIF, XMP and a color profile, so a WebP can carry camera details, dates, author names and GPS coordinates just like a JPEG. Many WebPs on the web have none, because the sites that create them strip it.

Does converting JPG to WebP remove metadata?

Not always. In our tests ImageMagick kept EXIF and GPS when it wrote a WebP, while Python's Pillow and browser-based converters dropped it. Check the converted file with ExifTool or webpmux if location data matters.

Can a WebP image contain GPS location?

Yes, inside its EXIF chunk. We made a WebP with GPS coordinates and ImageMagick carried them through a WebP to WebP and a WebP to PNG conversion. Re-encoding through a browser canvas removed them.

How do I strip metadata from a WebP file?

Re-encode it through a browser canvas, for example with an image compressor set to WebP output, or run exiftool -all= on the file. With ImageMagick, add -strip, because a plain conversion kept the metadata in our test.

Is lossless WebP different for metadata?

No. Lossless and lossy WebP use the same container, so both can hold EXIF and XMP. Our lossless test file kept its full EXIF block, the same as the lossy one.
