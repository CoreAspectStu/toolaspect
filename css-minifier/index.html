How the CSS Minifier Works

This is csso 5.0.5 (MIT), the CSS optimizer CSS-OSS toolchains have trusted for a decade, loaded from a CDN and running entirely in your tab. It's not a regex cruncher: csso parses your stylesheet into an AST, rewrites it, and regenerates clean CSS, which is why the output is valid even when the input had quirks a naive tool would mangle.

The math

Bytes saved = input − output; percent = (input − output) ÷ input × 100. The tool counts UTF-8 bytes, and when your browser supports CompressionStream it shows gzip sizes too — the honest number for anything served over HTTP, since text/html+css compresses well and raw savings overstate the network win.

How to use it

Paste a stylesheet (the Sample button loads ours), pick a preset, and the output updates as you type. Keep structure is the choice when you want byte-predictable output that still mirrors your source order. Restructure squeezes further by merging rules with identical selectors and discarding declarations that later rules override. Copy or download when you're happy; errors surface csso's own parse message with a line reference.

A worked example

The Sample button loads a 772-byte product-card stylesheet: a :root block of custom properties, three rules, a hover state, and a @media (max-width: 640px) override. Keeping structure takes it to 572 bytes — the comment goes, "Helvetica Neue", Arial, sans-serif keeps its quotes, 24px 24px 24px 24px folds to 24px, and 0px 0px 8px 0px trims to 0 0 8px. Restructuring reaches 555 bytes. Gzipped, that's 321 bytes across the wire — on a 772-byte file the gzip win (391 → 321) is smaller than the minify win, which is exactly why both columns are shown: minify first, then let transport compression do its job.

Custom properties and media queries ride through untouched in both passes — they're declarations and at-rules like any other, and csso merges only what the spec guarantees equivalent.

Frequently Asked Questions

What is the difference between keeping structure and restructuring?

Keeping structure only deletes whitespace, comments, and trailing semicolons — every rule stays where it was, so the cascade order is byte-for-byte predictable. Restructuring lets csso merge selectors that share a block, merge adjacent rules with the same selector, and remove overridden declarations. Same rendered result, smaller file, but the source order changes, which matters if you debug by line number or diff output against input.

How much smaller will my CSS get?

Hand-written CSS with comments typically loses 20-30% raw: our 772-byte sample goes to 572 bytes keeping structure (25.9%) and 555 bytes restructured (28.1%). Machine-generated CSS from Sass or Tailwind builds often shrinks more, because expanded nesting and duplicated vendor prefixes collapse. Over the wire the gap narrows — gzip already squeezes repetition — 321 versus 326 bytes on the same sample.

Does csso shorten colors and rewrite values?

Yes. csso folds #ffffff to #fff where equivalent, drops the leading zero on 0.10, collapses 24px 24px 24px 24px to 24px, trims 0px to 0, and removes units from zero lengths. Those rewrites are semantics-preserving by CSS specification, not heuristics — but if your pipeline asserts exact strings in visual regression tests, compare before shipping.

Is minified CSS safe for production?

Yes — csso parses your stylesheet into its own AST and regenerates it, so the output is valid CSS by construction, and it powers production toolchains behind the scenes. The one thing to keep in mind is specificity: restructuring preserves computed styles, but if you later patch the minified file by hand instead of the source, you lose the ability to re-minify cleanly. Always keep the unminified source as the source of truth.

Does restructuring break media queries or custom properties?

No. At-rule blocks like @media are minified inside-out and their contents merge only within the same query; custom properties (--brand and friends) are declarations like any other and pass through untouched. Our sample stylesheet uses both, and every pass preserves them — :root variables first, the max-width: 640px block intact.

Is my stylesheet uploaded anywhere?

No. csso 5.0.5 loads from a CDN into your browser and runs locally. Your CSS never leaves the tab — suitable for client work under NDA, though your employer's policy on pasting into third-party pages still applies.
